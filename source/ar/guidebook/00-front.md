# مرحباً بك في هندسة الواجهات الخلفية بالوكلاء الذكيين

أهلاً بك. خلال الأيام الخمسة القادمة ستبني واجهة برمجة خلفية (Backend API) حقيقية، بدءاً من مشروع Laravel فارغ وصولاً إلى خدمة منشورة يعمل بداخلها مساعد ذكي. وستفعل ذلك بالطريقة التي تعمل بها اليوم فرق محترفة كثيرة: مع وكيل برمجة ذكي (AI Coding Agent) يجلس بجانبك كشريك برمجة (Pair Programmer) سريع لا يتعب، ويخطئ أحياناً.

يقدّم هذه الدورة مركز نقلة للتدريب (NAQLA Training Center) في طرابلس، ليبيا. وهي مكتوبة للمتدرّبين والمهندسين المبتدئين. نفترض أنك تستطيع البرمجة بلغة واحدة على الأقل، وتعرف أساسيات Git ‏(clone، commit، branch)، وتستطيع كتابة استعلام SQL بسيط من نوع `SELECT`. ولا نفترض **أبداً** أنك استخدمت PHP أو Laravel من قبل. كل ما تحتاج إليه مشروح في هذا الكتاب أو في المختبرات.

## الركيزتان

يمرّ في كل يوم من أيام الدورة خيطان معاً. أبقِ الاثنين في ذهنك.

| الركيزة | ماذا تعني | مثال من الدورة |
|---|---|---|
| **البناء مع الوكلاء (WITH)** | تستخدم وكيل برمجة ذكياً (Claude Code، متصلاً بمشروعك عبر Laravel Boost) لتستكشف الشيفرة وتخطّط وتكتب وتختبر وتراجع. أنت المهندس، والوكيل شريك سريع. تتحقّق من كل شيء. | أن تطلب من Claude Code كتابة اختبارات Pest لـ `PricingService` قبل وجود الشيفرة، ثم تقرأ كل سطر يُنتجه. |
| **بناء الوكلاء داخل النظام الخلفي (INTO)** | تُطلق ميزات يستدعي فيها نظامك الخلفي نفسه نموذجاً لغوياً كبيراً (LLM): المخرجات المهيكلة، واستدعاء الأدوات، وحلقات الوكيل، والاسترجاع، وضوابط الحماية، والتقييمات، وضبط التكلفة. | «مساعد شحنة» (Shahna Assistant) على `POST /api/agent/chat`، الذي يستطيع تسعير الشحنات وتتبّعها والإجابة عن أسئلة السياسات بالعربية أو الإنجليزية. |

الركيزة الأولى تجعلك أسرع. والركيزة الثانية نوع جديد من عمل الأنظمة الخلفية. والمهندس الجيد في 2026 يحتاج إلى الاثنتين، وكل منهما تدعم الأخرى: فحين تفهم كيف يعمل وكيل مثل Claude Code من الداخل، يصبح بناء وكيل داخل منتجك أقل غموضاً بكثير.

## كيف تستخدم هذا الكتاب

هذا الدليل مرجعك خلال الأسبوع وبعده. وهو ليس ورقة المختبر. فالمختبرات (تُوزَّع منفصلة) تخبرك بالضبط بما تبنيه خطوة بخطوة. أما هذا الكتاب فيشرح *لماذا*، ويعطيك المفاهيم والمصطلحات، ويعرض شيفرة تعمل تستطيع المقارنة بها.

يتبع كل فصل من فصول الأيام البنية نفسها:

1. **أهداف التعلّم** — ما يجب أن تكون قادراً على فعله بنهاية اليوم.
2. **أقسام المفاهيم** — تطابق محاضرتي الصباح (الجلسة أ) وبعد الظهر (الجلسة ب).
3. **كيف تعمل مع وكيلك على هذا** — تعليمات (Prompts) عملية تنجح جيداً مع مهام اليوم.
4. **أخطاء شائعة** — أخطاء نراها في كل مرة ندرّس فيها هذه المادة.
5. **أهم الخلاصات** — ملخص قصير تستطيع إعادة قراءته قبل اليوم التالي.
6. **أسئلة التقييم الذاتي** — الإجابات في نهاية كل فصل. حاول الإجابة أولاً.

ستجد في أنحاء الكتاب ملاحظات داخل مربعات:

::: tip
النصيحة اختصار، أو عادة جيدة، أو توضيح يستحق أن تتذكّره.
:::

::: warning
التحذير يشير إلى شيء ينكسر عادةً، أو يُضيّع البيانات، أو يفتح ثغرة أمنية.
:::

::: agent
مربع «اسأل وكيلك» يحتوي على تعليمات تستطيع لصقها في Claude Code. عدّلها لتناسب حالتك. ولا تلصق تعليمات وتقبل الناتج أبداً دون أن تقرأه.
:::

::: checkpoint
نقطة التحقق (Checkpoint) تخبرك بما يجب أن يكون صحيحاً قبل أن تنتقل: اختبارات ناجحة، أو أمر يعمل، أو وسم Git ‏(Tag) بلغته.
:::

**الشيفرة في هذا الكتاب** تستخدم الأسماء نفسها المستخدمة في مستودع الدورة `shahna-api` (مثل `App\Services\PricingService` و`App\Enums\ShipmentStatus`). المقتطفات مختصرة لتوضيح الفكرة؛ والمستودع هو النسخة الكاملة. وحيث قد تتغيّر واجهة مكتبة ما بين الإصدارات، ننبّهك إلى ذلك ونخبرك أين تتحقّق.

## المشروع: شحنة للخدمات اللوجستية

«شحنة» (Shahna) شركة شحن ليبية خيالية. يحجز الزبائن شحنات بالشاحنات بين المدن الليبية. وأنت تنضم إلى فريق النظام الخلفي. مهمتك هذا الأسبوع بناء `shahna-api`، وهي واجهة برمجة Laravel واحدة تكبر قليلاً كل يوم.

### العمل في فقرة واحدة

يطلب زبون سعراً لنقل بضاعة (لنقل 500 كغ من الأثاث) من طرابلس إلى بنغازي في شاحنة صندوقية. تُرجع شحنة **عرض سعر** (Quote) صالحاً لمدة 15 دقيقة. فإن قبله الزبون، **يحجز شحنة** من ذلك العرض مع وقت للاستلام. ثم **يُسند** النظام **مركبة** من ناقل لديه شاحنة شاغرة من النوع والسعة المناسبين في مدينة الانطلاق. بعد ذلك تنتقل الشحنة عبر حالات متتالية حتى تُسلَّم. ويستطيع الزبائن **تتبّع** شحنتهم و**إلغاءها** ما دامت في مرحلة مبكرة. ويستطيع المرسِلون (Dispatchers) تجاوز الإسنادات يدوياً. وبحلول اليوم الرابع، يستطيع الزبائن أيضاً محادثة **مساعد شحنة** بالعربية أو الإنجليزية لإنجاز كل ذلك.

### المدن

تخدم شحنة ثماني مدن، لكل منها رمز من ثلاثة أحرف:

| الرمز | المدينة (EN) | المدينة (AR) |
|---|---|---|
| TIP | Tripoli | طرابلس |
| BEN | Benghazi | بنغازي |
| MRA | Misrata | مصراتة |
| SEB | Sebha | سبها |
| ZAW | Zawiya | الزاوية |
| TOB | Tobruk | طبرق |
| SRT | Sirte | سرت |
| GHA | Ghat | غات |

### قاعدة التسعير

```text
price_lyd = 50 + (km × rate_per_km[vehicle_type]) + (weight_kg × 0.02)
```

| نوع المركبة | السعر لكل كم (د.ل) |
|---|---|
| `van` | 0.8 |
| `box_truck` | 1.2 |
| `flatbed` | 1.5 |
| `reefer` | 1.9 |

الرسم الأساسي 50 ديناراً ليبياً. وتُقرَّب النتيجة إلى منزلتين عشريتين. والشحنة داخل المدينة نفسها تُحسب 0 كم.

### دورة حياة الشحنة

```text
pending ──> confirmed ──> assigned ──> picked_up ──> in_transit ──> delivered
   │            │             │
   └────────────┴─────────────┴──────> cancelled
```

لا يُسمح بالإلغاء إلا من الحالات `pending` أو `confirmed` أو `assigned`. وبمجرد استلام البضاعة، لا يمكن إلغاء الشحنة عبر واجهة البرمجة.

### اللحاق بالركب عبر وسوم Git

إن تأخّرت، فلن تبقى متأخراً. في المستودع وسم Git في نهاية كل يوم:

```bash
git fetch --tags

```

الوسوم: `day1-start`، `day1-end`، `day2-end`، `day3-end`، `day4-end`، `day5-end`. وكل وسم يجتاز `php artisan test` ‏(2 و23 و56 و80 و104 و135 اختباراً على التوالي).

## قائمة تجهيز البيئة

أكمل هذه القائمة **قبل اليوم الأول**. فمشكلات التجهيز تلتهم وقت المختبر.

| العنصر | كيف تتحقّق | ملاحظات |
|---|---|---|
| Docker Desktop مثبّت ويعمل | `docker info` يطبع تفاصيل الخادم | امنح Docker ذاكرة 4 GB على الأقل |
| Git | `git --version` | اضبط `user.name` و`user.email` |
| VS Code أو PhpStorm | يفتح مجلد المشروع | في VS Code: ثبّت إضافة "PHP Intelephense" |
| Node 20 أو أحدث | `node --version` يُظهر v20+ | يحتاج إليه Claude Code وأدوات الواجهة الأمامية في Laravel |
| Claude Code CLI | `claude --version` | ثبّته من وثائق Anthropic الرسمية |
| مفتاح Anthropic API | يقدّمه المدرّب في اليوم الأول | لا تودعه أبداً. مكانه `.env` فقط |
| استنساخ المستودع | `git clone https://github.com/OthmanHaba/shahna-api.git` | يشارك المدرّب الرابط |
| تشغيل الحاويات | `./vendor/bin/sail up -d` ثم `./vendor/bin/sail artisan test` | التشغيل الأول ينزّل الصور؛ افعله على اتصال إنترنت جيد |

::: tip
أضف اسماً مستعاراً (Alias) في الطرفية لتكتب `sail` بدلاً من `./vendor/bin/sail`:
`alias sail='sh $([ -f sail ] && echo sail || echo vendor/bin/sail)'`
:::

::: warning
مفتاح API كلمة مرور تكلّف مالاً. احفظه في `.env`، وهو مُدرج في `.gitignore`. وإن لصقته يوماً في إيداع (Commit) أو محادثة أو لقطة شاشة، فأخبر المدرّب ليُستبدل المفتاح.
:::

::: checkpoint
أنت جاهز حين يطبع `sail artisan test` نتيجة خضراء، ويفتح `claude` داخل مجلد `shahna-api`.
:::

## ميثاق استخدام الذكاء الاصطناعي

الوكلاء الذكيون مسموح بهم ومتوقَّع استخدامهم في هذه الدورة. إنهم أداة، لا مؤلِّف. وتنطبق هذه القواعد في المختبرات، وفي المشروع الختامي (Capstone)، وفي عملك بعد ذلك.

1. **أنت مسؤول عن كل سطر تودعه.** إن كتبه الوكيل وكان خاطئاً، فهو خطؤك أنت. وعبارة «الذكاء الاصطناعي فعلها» ليست تفسيراً مقبولاً أبداً في مراجعة الشيفرة.
2. **اقرأ قبل أن تقبل.** اقرأ كل فرق (Diff). وإن لم تفهم سطراً، فاطلب من الوكيل شرحه، ثم قارن الشرح بالوثائق.
3. **تحقّق بالدليل.** اختبارات، أو طلب يعمل فعلاً، أو خطة استعلام، أو نتيجة اختبار حِمل. أما «الوكيل قال إنها تعمل» فليس دليلاً.
4. **لا تلصق الأسرار.** لا مفاتيح API، ولا كلمات مرور، ولا بيانات زبائن حقيقية في التعليمات.
5. **كن صادقاً بشأن استخدامك للذكاء الاصطناعي.** في عرض مشروعك الختامي ستشرح ما فعله الوكيل وما فعلته أنت. والصدق جزء من الدرجة.
6. **ابقَ متحكّماً في الآثار الجانبية.** لا تدع وكيلاً يشغّل أوامر مدمّرة (حذف قواعد البيانات، أو الدفع القسري، أو حذف الملفات) دون أن تقرأ الأمر أولاً.
7. **تعلّم، ولا تكتفِ بالنسخ.** إن حلّ الوكيل مشكلة لم تكن لتحلّها، فخذ خمس دقائق لتفهم الحل. هكذا تنمو.

هذه القواعد ليست عن عدم الثقة. إنها ما يجعلك محترفاً يُحسن استخدام الأدوات القوية.
